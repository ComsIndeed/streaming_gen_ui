# Release Notes — Version 0.2.1

## Overview
Version `0.2.1` focuses on improving graph streaming responsiveness, handling intermediate network state errors safely, and updating instructions for widget registry integration.

---

## 1. Progressive Graph Bar Rendering
We overhauled graph rendering during active stream compilation:
* **Immediate Animating:** The bar graph widget now uses the `.onElement` progressive stream listener on the `values` and `labels` lists.
* **Responsive Growth:** Bars start painting and animating immediately as individual numerical tokens start appearing in the stream, rather than waiting for the entire list block to finish streaming from the LLM.

---

## 2. Graph Cast Exception Protection
Addressed runtime type-casting crashes during active streaming:
* **Cast Safety:** Handled `type 'Null' is not a subtype of type 'num' in type cast` crashes that occurred when graph lists contained null placeholder elements during intermediate parsing passes.
* **Safe Filtering:** Implemented robust `.whereType<num>()` array filters, guaranteeing stable layout calculations even under incomplete or corrupted stream inputs.

---

## 3. Streaming Network Image URL Protections
Prior versions suffered from image compilation failures when network URLs were streamed character-by-character:
* **Wait for Resolution:** `BaseStreamingImage` was refactored to accept a `PropertyStream` and asynchronously await the fully completed `imageUrl` value via `FutureBuilder`.
* **Zero Crashes:** Bypasses intermediate, partially-streamed invalid URLs (which previously threw layout network rendering exceptions), displaying a smooth theme-aware shimmer skeleton until the URL is 100% complete.

---

## 4. Integration Instruction Cleanups
* **Registry Overhaul:** Fixed legacy arithmetic `+` merge registry code examples in integration documentations.
* **Correct Syntax:** Standardized setup examples to correctly utilize modern, list-based `.only()` registry filters.
