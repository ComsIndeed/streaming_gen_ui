# Release Notes — Version 0.2.2

## Overview
Version `0.2.2` is a patch release focusing heavily on solving layout shifts, mounting flickers, and rendering-loop layout crashes when viewing completed or historical chat bubbles in a `reverse: true` scroll view.

---

## 1. Zero-Frame Synchronous Hydration (`AdaptiveStreamBuilder`)
Standard `StreamBuilder` widgets enforce a 1-frame asynchronous microtask delay during initialization. Even if data is available synchronously (e.g. from stream replays), they render their initial waiting state (often empty) on Frame 1, and pop their contents on Frame 2.

We introduced `AdaptiveStreamBuilder<T>` to completely resolve this:
* **Frame-1 Hydration:** During `initState()`, if animations are disabled (meaning the card is historical/completed), `AdaptiveStreamBuilder` instantly pulls the cached property map (`latestProperties`) from the ancestor `StreamingUiProvider` and seeds its state synchronously.
* **0-Frame Delay:** Historical messages mount fully rendered on Frame 1, completely eliminating flashing placeholders and layout shifts.

---

## 2. Adaptive Height Snapping (`AdaptiveAnimatedSize`)
Using standard `AnimatedSize` on list items can trigger layout recursion crashes under fast scroll speeds:
> `A RenderAnimatedSize was mutated in its own performLayout implementation. A RenderObject must not re-dirty itself while still being laid out.`

`AdaptiveAnimatedSize` solves this:
* **Animation Bypassing:** When `StreamingUiProvider.disableAnimations` is true, the widget completely bypasses `AnimatedSize` and renders the raw child directly on Frame 1.
* **Instant Bounds Snapping:** Historical cards immediately snap to their exact final height boundaries, eliminating layout recursion and keeping fast scroll operations completely crash-free.

---

## 3. Scope-Safe Direct Lookups for Lists
Many themed cards previously used nested `StreamBuilder` widgets to progressive-render child arrays (e.g., forecast details, todo items, note tags). These caused massive layout popping on Frame 2.

We replaced these nested builders with direct, synchronous map lookups:
* We introduced a private `_latestData` map inside the card `State` classes to cache the outer builder map snapshot.
* Swapped nested `StreamBuilder` lists for simple `Builder` widgets reading `_latestData["forecast"]`, `_latestData["items"]`, etc.
* Since the outer builder already reacts to property changes, this preserves full reactivity during streams while delivering **100% synchronous rendering** for nested structures when completed.

---

## 4. Layout & Text Optimization
* **`TextBlock` Future-Bypassing:** If a text block is completed (`isClosed` is true), it completely bypasses the `AccumulatingStringStreamBuilder` and immediately paints the joined text chunks on Frame 1.
* **`StreamingColumn` & `StreamingRow` Hydration:** Layout columns and rows now check if the stream is closed, querying their children list synchronously from `latestProperties?["children"]` on Frame 1.
* **`StreamingStepper` Hydration:** Accordion steppers synchronously load all step maps from `latestProperties?["steps"]` when completed.
* **Synchronous Graph Setup:** In `initState()` of completed graphs, labels, values, headers, and rows are populated synchronously from `latestProperties` so the chart paints immediately.
